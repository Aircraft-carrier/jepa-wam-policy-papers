# Paper Card Template

Copy this structure to `papers/<arxiv-id>-<short-slug>.md`. Replace every placeholder with source-backed content or mark it as `待核对`.

```markdown
# <论文标题>

## 1. 基本信息
- 作者：<作者>。
- 单位：<单位>。
- 日期：首次提交 <YYYY-MM-DD>；阅读版本 <vN>，更新于 <YYYY-MM-DD>。
- 链接：[arXiv](<URL>) · [HTML](<URL>) · [PDF](<URL>) · [代码](<URL 或待核对>) · [模型](<URL 或待核对>)。
- 类型：<直接相关 / 邻近 / 背景；encoder、WAM、policy 或组合>。

## 2. 一句话摘要
<一句话说明输入、预测目标、动作/策略输出和主要结论。>

## 3. 主要创新点
- <创新点及其对应证据位置>。

## 4. 方法与训练信号
- <encoder 是否冻结、token/feature、预测目标、动作表示、损失、条件化和推理流程>。

## 5. Benchmark / 测评方法 / 结果
<写清任务、split、episode/rollout 数、指标、baseline、表号和最终/消融结果。>

## 6. 可视化与表示分析
- <图、probe、attention、embedding 分析；没有则写“未见明确分析”。>

## 7. 真机实验与泛化
- <平台、任务、rollout、指标，以及新任务/物体/场景/embodiment/指令的具体泛化设置>。

## 8. 与 OpenWAM 的关系
<说明可复用模块、可比较变量和不应直接比较的设置。>

## 9. 局限与待核对项
- <证据缺口、预训练规模差异、指标定义、代码/正文差异和需要继续核对的内容>。

## 10. 先建立直觉
### 10.1 这篇论文到底要解决什么问题
<用不超过三段话解释旧方法为什么不够，以及本文把问题改写成了什么。>

### 10.2 读者可以先记住的类比
<用一个不依赖公式的类比解释 encoder、latent、world model、policy 或 planner。>

## 11. 逐步读方法
### 11.1 数据流
<按时间顺序写清 observation、视觉表示、动作/语言条件、未来预测和最终动作。>

### 11.2 训练时与推理时
<分开写训练阶段实际输入的标签/未来帧/动作，以及部署阶段能获得的信息。>

### 11.3 关键模块与张量含义
<解释 token/feature 的语义、预测 horizon、动作 chunk、冻结模块和可训练模块。公式可以使用行内 LaTeX，但必须配中文解释。>

## 12. 训练目标为什么合理
- <每个 loss 或 supervision 试图让模型获得什么能力。>
- <该目标没有约束什么，以及可能的 shortcut 或 failure mode。>

## 13. 结果应该怎样读
### 13.1 哪个实验回答哪个问题
<把主结果、消融、泛化、表示分析和定性可视化分别对应到研究问题。>

### 13.2 不要过度解读的地方
<写清指标、数据规模、baseline、推理预算和仿真/真机边界。>

## 14. 复现与对比清单
- 数据与预处理：<待核对或已确认内容>
- 表征与模型：<encoder、尺寸、冻结/微调状态>
- 训练与推理：<loss、horizon、动作表示、规划/采样预算>
- 评测：<任务、split、seed、episode、指标和对照组>
- 公平对比：<哪些变量必须保持一致>

## 15. 读者 takeaway
- **可以直接借鉴：** <方法或实验设计>
- **不能直接推出：** <论文没有证明的结论>
- **最值得复现：** <最小实验>
- **最值得继续验证：** <开放问题>
```

## Evidence wording

- `原文报告`：数字或设置在正文、表格、图注或附录中直接出现。
- `论文代码确认`：论文未明确，但官方代码或配置可以确认；同时保留代码链接。
- `待核对`：只有摘要、搜索结果或二手资料支持，不能写成已确认事实。
- `未见明确分析`：检查过正文/附录相关位置，但没有找到该类分析；不要写成“论文没有”。
